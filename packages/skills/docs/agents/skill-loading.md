# Load a named skill

Reference tokens identify skills and apps; they do not execute tools. Read `docs/agents/capabilities.md` and this host’s adapter before resolving an invocation. Preserve disable-model-invocation and agents/openai.yaml policy. When Justin names a skill, run it. If the host refuses because the skill is user-only, Read its `SKILL.md` in the loaded plugin's own folder on disk and follow it, with the rest of his message as its arguments. Start a user-only skill only when he names it, or under an autopilot grant (`skills/oneezy/oneezy-agents/references/AGENTS-GLOBAL.md`). Run a skill only from a loaded plugin (its folder on disk counts) or the repo's own skills; never fetch a `SKILL.md` from GitHub, or read one from any other folder, to run it (ADR-0011); when a typed skill does not resolve, show the per-harness invocation table (`docs/agents/library.md`, Calling a skill; the harness's global block carries the same one).

For Brain requests load the actual `/oneezy-brain` skill (its `SKILL.md`), then its location, capability and operation references. It owns current routing. If a library skill is missing, run `/oneezy-skills` (its script, a plain sync of the latest release; in a cloud thread the setup line `npx --yes @oneezy/skills-sync@latest --quiet`), finish the manual steps it ends with, then verify the skill is visible in a fresh session. The latest release cannot stand in for a held draft rollout; that uses the reviewed tool and library under the current rollout scope.
