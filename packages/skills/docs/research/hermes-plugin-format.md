# Hermes plugin format

## Summary

**Go.** Hermes Agent (NousResearch/hermes-agent, release v0.21.6 / 2026.9.24, main at c5733167) loads "portable Agent Plugins v1" packages: a directory with a root `plugin.json` (`$schema` `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`) and `skills/<name>/SKILL.md`, which is the layout the library already builds under `plugins/<id>/`. It installs them from GitHub (`hermes plugins install oneezy/skills/<path>/<id> --no-enable [--ref <40-hex sha>]`: a sparse clone of that subdirectory into `<HERMES_HOME>/plugins/<id>`), switches them on with `hermes plugins enable <id>` (`plugins.enabled` in `config.yaml`), refreshes them with `hermes plugins update <id>` and removes them with `hermes plugins remove <id>`. No registry, catalog or downloaded copy is needed.

The blocker, and the rejection Justin saw: Hermes's portable validator requires a skill's `metadata` to map string keys to string values. `metadata.internal: true` is a YAML boolean, so every skill of every library package is skipped with "metadata must map string keys to string values" and the package loads with no skills. The loose-skill loader never checks this, which is why the loose form works today. The `skills` CLI needs the literal boolean (`metadata.internal === true`), so one file cannot satisfy both: the generator must build the copies Hermes reads without the flag (see "What tools#153 must do"). Two pstack skills (`make-bot-ui`, `poteto-mode`, `name` differs from the folder) and `matt-pocock/pr` (nested `metadata.credits`) fail other rules and need a rewrite in the Hermes copy.

Cost to weigh before building: Hermes namespaces every plugin skill. The library's skills become `agent-plugin-<id>-<hash>:<skill>` (for `oneezy`: `agent-plugin-oneezy-80c7eb0f:oneezy-brain`) in `skills_list`, the system prompt index and the slash menu; bare `/oneezy-brain` is what a loose skill gets. Plugin skill names never collide with loose ones, which is what ADR-0007 asks for.

### 3. Plugins: native and portable

- Roots: bundled `<repo>/plugins/`, user `<HERMES_HOME>/plugins/`, project `./.hermes/plugins/` (only with `HERMES_ENABLE_PROJECT_PLUGINS`), pip entry points `hermes_agent.plugins`. Later roots win on key collision (project > user > bundled). [plugins_discovery.py:189-255; plugins.md "Plugin discovery"] verified
- Accepted layouts: flat `<root>/<name>/plugin.yaml|plugin.yml` or one category level `<root>/<cat>/<name>/plugin.yaml` (depth capped at two); "portable `plugin.json` packages are accepted alongside YAML manifests"; `plugin.yaml` wins when both exist. A top-level child named `.claude-plugin`, `.codex-plugin`, `.cursor-plugin`, `.devin-plugin` or `.kimi-plugin` is skipped as a "foreign-harness manifest convention"; dunder dirs are skipped. [plugins_discovery.py:30-36, 134-187] verified
- Native manifest `plugin.yaml`: `name version description author requires_env provides_tools hooks|provides_hooks kind (standalone|backend|exclusive|platform|model-provider) label optional_env platforms external_dependencies pip_dependencies python_dependencies requires_plugins requires_hermes config_schema manifest_version (<=2) api_version license homepage tags capabilities emits listens provides_locales ...`; unknown fields warn and load. Code lives in `__init__.py` `register(ctx)`; skills ride along through `ctx.register_skill(name, path)`, served as `<plugin>:<name>`, "Not copied into ~/.hermes/skills/". [plugins_manifest.py:27-39, 520-560; plugins_content.py:22-52; plugins.md "Quick overview", "What plugins can do"] verified
- Portable Agent Plugins v1, "a compatibility adapter", "an explicit supported subset, not a claim of full Agent Plugins conformance": root `plugin.json` must be a regular in-root file; `$schema` must equal `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json` (else fatal "unsupported or missing Agent Plugins schema"); `name` 1-64 chars matching `^(?!.*(?:--|\.\.))[a-z0-9](?:[a-z0-9.-]*[a-z0-9])?$`; `version description homepage repository license` strings; `keywords` array of strings; `author` an object with only string `name email url`; `extensions` values objects (Hermes reads `extensions["com.nousresearch.hermes"].servers`; other namespaces such as `com.openai` are carried and ignored); unknown top-level fields are dropped with a diagnostic. Components: `skills/<dir>/SKILL.md` and `mcp.json` (stdio, streamable-http; `sse` skipped). [agent_plugins.py:45-56, 175-207, 247-282, 404-437; developer-guide/plugins/index.md:58-150] verified
- Portable skill rules: `name` must be a string equal to the folder name, 1-64 chars, `^(?!.*--)[a-z0-9]+(?:-[a-z0-9]+)*$`; `description` a non-empty string of at most 1024 chars; optional `license` string, `compatibility` string of 1-500 chars, `metadata` "must map string keys to string values", `allowed-tools` string; every other key is ignored. `skills/` must be an in-root directory and each SKILL.md a regular in-root file (a symlink that leaves the root fails that skill). A failing skill is skipped with diagnostic `skill:<dir>` while its siblings load; the loader logs `Agent Plugin '<key>' [skill:<name>]: <message>`. The test `test_rejects_invalid_optional_skill_fields` feeds `metadata: []` and asserts `package.skills == ()`. [agent_plugins.py:209-282; plugins_loader.py:625-640; tests/hermes_cli/test_agent_plugins.py:195-212] verified. That this rule is what Justin's install hit: inferred (it is the only place a `metadata` value type is checked, and a YAML `true` is a bool).
- Namespace: the plugin key is the manifest `name` for a flat user plugin; the skill namespace is `agent-plugin-<slug>-<sha256(key)[:8]>`, "derived from the discovered plugin key so sanitized names cannot collide"; `oneezy` gives `agent-plugin-oneezy-80c7eb0f`, so the skill is `agent-plugin-oneezy-80c7eb0f:oneezy-brain`. Plugin data: `<HERMES_HOME>/plugin-data/<namespace>`. [plugins_manifest.py:59-68, 489-500; plugins_loader.py:630-632; digest computed with hashlib] verified
- Where plugin skills show: `skills_list` (category `plugin`, qualified name), the `<available_skills>` system-prompt index, interactive slash commands `/<qualified, lower-cased>` (skipped when it collides with an existing command), `skill_view("ns:skill")`; a loaded skill carries a "Bundle context" banner naming its siblings. "Plugin skills use their own `plugin:skill` names and never collide with these." [skills_tool.py:248-276; prompt_builder.py:1320-1335, 1572-1580; skill_commands.py:555-612; skills_tool_plugin.py:132-170; skills.md:509] verified
- Opt-in: a user plugin is discovered but not loaded until its key is in `plugins.enabled` in `config.yaml`; `plugins.disabled` wins; `hermes plugins enable <key>` / `disable <key>` edit the lists. [plugins_discovery.py:112-133, 257-311; plugins.md "Plugins are opt-in"] verified
- `requires_hermes` exists for `plugin.yaml` only; a portable manifest has no Hermes version gate. [plugins_manifest.py:489-500] verified

### 4. Installing from GitHub

- `hermes plugins install <identifier> [--force] [--ref SHA] [--allow-removed] [--enable|--no-enable] [--yes-deps] [--no-deps]`. The identifier is a catalog entry name, a Git URL, or `owner/repo[/sub/dir]` shorthand (`owner/repo#subdir` and `https://github.com/o/r/tree/<ref>/<subdir>` are parsed too) and resolves to `https://github.com/owner/repo.git` plus the subdirectory. A non-catalog source prints "custom (unreviewed) source". [plugins_cmd.py:289-345; subcommands/plugins.py:38, 46; cli-commands.md:1646; plugins_cmd_install.py:562] verified
- Clone: `git clone --depth 1` into a temp dir under `plugins/`; a subdirectory install adds `--filter=blob:none --no-checkout` and a sparse checkout of that folder ("downloads only that folder's files"). `--ref` must be a full 40-hex commit (branches, tags and short SHAs are rejected) and is checked out detached and verified; without it the clone is of the remote default branch. Needs a `git` executable; anonymous first, then `GITHUB_TOKEN`/`GH_TOKEN`, `gh auth`, the git credential helper. [plugins_cmd_git.py:207-257; plugins.md "For a reproducible install", "Installing from a private repository"] verified (default-branch wording inferred from `git clone` without a ref)
- Name and target: `plugin_name` = the manifest `name` (portable `plugin.json` included), else the subdirectory's last segment, else the repo name; the tree is published to `<HERMES_HOME>/plugins/<name>` (flat; a `/` in the name is refused). If that path is already a symlink or junction the install fails: "Plugin '<name>' is already installed outside the catalog: <link> is a link to <target>. Delete that link". Installing a name that exists needs `--force`. [plugins_cmd_install.py:383-440] verified
- Record: `plugins/.install-metadata.json` gets `{pinned, revision, source: "<url>#<subdir>"}` for the name; the tree is swapped in atomically after a Python-dependency consent step that a skills-only package does not trigger. [plugins_cmd_install.py:443-486; plugins_cmd_git.py:33-60, 193-195] verified
- Security scan (`tools/plugin_guard.py`, the hub's `skills_guard` engine with the full pattern set on docs and config files): `safe` proceeds, `caution` needs confirmation (a TTY prompt, or `--force`), `dangerous` is always blocked; `plugins.scan_on_install` in config.yaml can turn scanning off. [plugins_cmd.py:188-225; plugin_guard.py:1-8] verified. The verdict for the library's packages was not measured.
- Portable checks at install: `plugin.json` is validated (a failure is `manifest_invalid`); the "unavailable portable plugin" refusal concerns MCP server declarations only; a tree with none of `plugin.yaml`, `plugin.json`, `__init__.py` only warns. [plugins_cmd_install.py:234-258, 298-320, 604-607] verified
- Enable: `Enable '<name>' now? [y/N]` unless `--enable`/`--no-enable`; `--enable` writes `plugins.enabled`. [plugins_cmd_install.py:614-673] verified
- Update: `hermes plugins update <name>` refuses a pinned install (move it with `install --force --ref <sha>`), runs `git pull` in a full clone, and for a tree without `.git` (a subdirectory install) re-installs from the recorded source; edits to tracked files are copied aside under `plugins-backup/`. [plugins_cmd_update.py:23-27, 70-90; plugins.md] verified
- Remove: `hermes plugins remove <name>` deletes the tree and its install-metadata row and keeps the config lists consistent. [plugins_cmd_remove.py:1-5, 104] verified
- Catalog: `plugin-catalog/*.yaml` in hermes-agent, maintainer-merged PRs with mandatory 40-hex SHA pins; `hermes plugins install <name>` resolves a bare name there. Not needed for a custom source. [plugin-catalog/README.md] verified
- Hermes Desktop has "Skills -> Plugins -> Install from Git" with a "Pin to commit" field. [plugins.md] verified

### 6. Loose copies from GitHub without a library on the machine (the fallback)

- Skills Hub, GitHub source: `hermes skills install owner/repo/path/to/skill` installs one skill without a tap; `hermes skills tap add owner/repo` subscribes to a repo whose skills sit one level under `skills/` (per-tap `path` editable in `<HERMES_HOME>/skills/.hub/taps.json`; folders starting with `.` or `_` ignored). Installs are real copies into `<HERMES_HOME>/skills/`, quarantined, security-scanned and recorded in `.hub/lock.json`; `hermes skills update` refreshes them. "Third-party URL and GitHub installs include `SKILL.md` plus the exact local files it references under `references/`, `templates/`, `scripts/`, `assets/`, and `examples/`. Unreferenced repository files are not copied"; a bundle containing a symlink is refused. The library's grouped `skills/<group>/<name>` does not fit a tap's one-level default, `plugins/<id>/skills/` does (one tap entry per plugin). [skills.md:335-363, 795-832, 950-1060; skills_hub_install.py:175-183] verified; whether "referenced files only" keeps every library skill whole: inferred no (scripts a SKILL.md never names are dropped).
- `skills.external_dirs` pointing at one folder of real copies the tool maintains gives bare `/name` without per-skill links. [section 2] verified

## What tools#153 must do

1. Generator (`packages/skills-sync/src/build.ts`): the copies Hermes reads must carry only string-valued `metadata`, and `name` must equal the folder. The same files serve Claude Code, Codex and the `skills` CLI, which needs the boolean, so build a second rendering for Hermes rather than change `plugins/<id>`: `dist/hermes/<id>/` with the same `plugin.json` and `skills/<name>/**`, where the root SKILL.md keeps string metadata entries, drops `internal` and nested maps (`matt-pocock/pr` `credits`), and sets `name` to the folder (`make-bot-ui`, `poteto-mode`). `dist` is in the `skills` CLI's `SKIP_DIRS`, so `npx skills add oneezy/skills` keeps listing each skill once; Claude Code and Codex never look there. `build --check` compares both trees; `catalogs()` and the two marketplaces stay as they are; NOTICE.md says where the Hermes copy is. The alternative that avoids the duplicate bytes, dropping the flag everywhere and moving all packages under `dist/` with `metadata.pluginRoot` (the probe's d2), changes the paths the claude.ai and Codex marketplaces already import, so leave it for its own ticket. Extend `test/build.test.ts` for the Hermes rendering.
2. Harness table (`src/harnesses.ts`): Hermes's `configDir` is `HERMES_HOME`, else `%LOCALAPPDATA%\hermes` on win32, else `~/.hermes`; a named profile is `<configDir>/profiles/<id>` with its own `plugins/`, `skills/` and `config.yaml` (the default profile is the home itself).
3. Sync flow, per plugin id, in this order: refuse to proceed if `<HERMES_HOME>/plugins/<id>` is a link (Hermes would); `hermes plugins install oneezy/skills/dist/hermes/<id> --no-enable [--ref <library commit>]`; `hermes plugins enable <id>`; verify (`plugins/.install-metadata.json` has the name, `config.yaml` lists it under `plugins.enabled`, `hermes plugins list` shows it); only then remove that plugin's loose links from `<HERMES_HOME>/skills/`. A second sync finds the name installed and enabled and runs `hermes plugins update <id>` (or nothing when `--ref` pinned the same commit); a failed install leaves the loose links in place. Add a `hermes` CLI to `test/fixtures/fake-harness` with the `install`, `enable`, `list`, `update` and `remove` shapes above.
4. Scan verdicts: `dangerous` can never be installed, `caution` needs a TTY answer or `--force`. Decide whether the tool passes `--force` on the first install or reports the verdict for Justin to answer once.
5. Say in the README and the sync output that Hermes lists the skills as `agent-plugin-<id>-<hash>:<skill>` and that `/agent-plugin-oneezy-80c7eb0f:oneezy-brain` is the slash form; the bare `/oneezy-brain` only exists for a loose skill or a native `plugin.yaml` package.
