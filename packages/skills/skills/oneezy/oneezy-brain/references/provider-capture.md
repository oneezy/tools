# Provider capture contract, version 1

This is the reusable interface for configured native provider readers. It creates no schedules, sends no messages and stores no credentials. Read the current private registry and ingestion instructions first; disabled or unconfigured sources remain disabled.

Private configuration is `{contract_version:1,enabled,initial_lookback:{email_days:7,calendar_days:14},overlap_hours:48,sources:[{source_key,provider,account_email,scope:{kind,id},enabled}]}`. Each exact mailbox or calendar has its own source_key and observed scope id. Scope kind is mailbox or calendar. Keep the existing caller times and private automation identifiers in configuration, outside this repository.

Load `scripts/provider-capture.mjs`. `coverageWindow(config,source_key,asOf,checkpoint)` uses initial email seven-day/calendar fourteen-day lookback, then the source's verified-success checkpoint minus 48 hours. Its after/through bound modified-item reads; calendar_from/calendar_through also retain the full fourteen days before and after asOf on every pass. Translate both constraints into the native reader's supported filters. Page through every bounded result; preserve exact accounts, exclusions and scopes. Never claim coverage from a truncated search or an unsupported filter.

Each observed item has `{source_key,provider,account_email,scope_id,item_id,subject,revision:{kind,value},source_url,source_updated}`. The last two fields are observed strings or null. A revision is the provider's actual etag, revision or updated_at value; when absent, use `fingerprint(observedMaterial)` over the actual relevant source content. Never substitute a constant or a fabricated timestamp. Identity retains provider/account/scope/item_id. Look up that identity and its canonical immutable Brain ID before writing; changed revisions update the same record under the agreed mapping. New outside material goes to Inbox, and source deletion becomes review rather than history deletion.

Map only supported source facts to live Schema editable fields and use the guarded native planner in `references/operations.md`. Subject is the observed source subject in the envelope and the canonical subject in the receipt; preserve both if their approved mapping differs. Read back the saved ID, canonical subject and destination. Only then call `verifiedReceipt(config,envelope,{ID,subject,action,destination},readback,verified_time)`, with readback normalized from the actual native result. Action is capture, update, unchanged or review; destination is Inbox or Backlog. Persist this receipt privately after readback.

Advance a source checkpoint with `advanceCheckpoint(config,source_key,through,items,receipts,coverage)` only after complete scoped reads and every item's exact revision has a verified receipt. Coverage is `{source_key,through,complete:true,all_pages_read:true,failures:[]}`, constructed from the actual reader's successful pagination, including an empty result. A read, mapping, write or verification failure prevents advancement for that source. Continue independent sources. Interrupted retries retain the same identity, ID and Doc; report observed coverage and failures.
