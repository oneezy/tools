# ChatGPT adapter

Use current advertised capabilities as authority. In ChatGPT Work, the current session supports paginated `skills.list` and `skills.read` using returned packages/resources. Follow every cursor when resolving duplicates. If code mode exposes ALL_TOOLS, filter names/descriptions, read the selected tool schema and call through tools; if tool_search is advertised, use it instead. Neither route exists universally. Never use MCP resource listing as an app inventory.

The composer’s @ selector is a human selection route for plugins/skills, not an API call made by mentioning a name. Load the catalog’s actual Google Drive, Google Sheets and Google Docs skills, then call exposed Google Drive tools: fetch for registry/file text; get_spreadsheet_metadata then bounded get_spreadsheet_range/cells; get_document for native Docs. Choose the authorized account from current tool metadata. Re-discover before writes. Historical Pages use exposed Pages read APIs; authorized page edits load pages:write-page or the appropriate actual Pages skill.

For Oneezy Skills discovery/install/connect, load `plugin-management:plugin-management` and use current search_plugins/get_plugin_dependencies/get_app_permissions APIs as needed. A search is non-exhaustive; get_plugin_dependencies covers public globally listed plugins and cannot inspect every private personal plugin. Suggest only required missing eligible plugins through suggest_plugins; the user completes connection. Verify connected tools and an authorized read before claiming access. Permission mutation/removal needs the specific user request; neither is a sync default.

For skill authoring, load the actual `skill-creator` instructions, then perform its source-authoring workflow in oneezy/skills. For plugin creation/update load `plugin-creator:create-plugin` or `plugin-creator:update-plugin` according to the selected source. Source-managed plugins use their owning repository/release path. For an eligible account plugin, call get_plugin_files with its verified backend ID, paginate, retain current_release_id, build a changed-file archive, then—only when publication is authorized—call update_plugin with expected_release_id and read back changed files. Current advertised update API supports explicit delete_paths; the older account-updates reference saying deletion is impossible is stale for this API. Verify current schema before any deletion; never infer deletion from omitted files. Do not create another plugin or remove the old one as an automatic workaround. Justin's typed `@oneezy-skills update my ChatGPT plugins to the latest oneezy/skills release` is that authorization, for exactly the writes `references/chatgpt-update.md` lists.

A source-only request performs authoring/packaging and reports cloud upload held. If the native API is technically unavailable, follow another currently advertised supported creator route; if none exists, report the exact blocker. A cloud terminal/npx route to ChatGPT upload is unknown/unsupported here. Claude/Codex plugin CLIs and local links do not upload ChatGPT account plugins.
