# Global block

Use this for an audit of a harness's global block, a development build of the tool, or a desktop handoff. The tool writes one managed block into each harness's global instructions file (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, under `CLAUDE_CONFIG_DIR` and `CODEX_HOME` when set) and nothing into a repository (ADR-0011). Its text is the tool's own pointer: load `/oneezy-agents` at session start and follow what it loads, plus the invocation table (oneezy/tools#205). Justin's rules live in that skill's own `references/AGENTS-GLOBAL.md` and reach a session with the plugin release that carries them. `/oneezy-brain` owns Brain account, locations and schema; `agents.md` only points at it.

1. Inspect current state: `status --json` gives each harness's `block` (`status`: `current`, `missing`, `outdated`, `hand-edited`, `unknown` or `conflict`) and `repoBlocks`, the blocks an older version left in repository files. Justin removes those by hand, or an agent does as a change he asked for in that repository. Check existing rollout branches in oneezy/tools. Preserve dirty work and pinned sources.
2. Change the tool (the pointer text is in `packages/skills-sync/src/block.ts`) in an isolated development checkout. Follow Justin's requested development or review scope; a desktop handoff or a request to avoid publication stops before the Land workflow.
3. Build and test the reviewed tool. Point `SKILLS_SYNC_CLI` at its built `dist/src/cli.js`; both platform scripts run that file through Node. For a published rollout, clear that variable and use the latest published tool. Run the script with `sync --plan --json`; this step is done when every harness, block, hook entry and plugin action is accounted for.
4. Run the same script without `--plan`. The tool changes only the bytes between its markers, keeps every other byte and line ending, refuses a broken or doubled marker pair and a hook file it cannot edit, and reads its writes back. A conflict fails the run; resolve it before retrying. Record the exact tool and library commits and every resulting path.
5. Run the script with `status --json`. Done is `ok: true` and `manualSteps: []`; list any open step. Then start a fresh host session and check that its loaded instructions route a Brain lookup through `/oneezy-brain`. File readback alone does not prove automatic invocation or Drive connector access.

For a desktop handoff, supply the exact commits, build and test results, plan, apply and status commands, and the host prerequisites. A coordinating task may dispatch them to an existing authorized desktop task. Report each inaccessible computer, WSL distro or connector as a blocker. A cloud test, prepared handoff or dispatch is not desktop execution.

Hermes has no global instructions file, so it has no block. System policy, harness settings and additional instruction directories need separate host inspection.
