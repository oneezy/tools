# Historical Skills/Status aliases

Use this branch only for an explicitly authorized handoff of the eight historical `oneezy-skills` and `oneezy-status` links on Justin's Windows/Ubuntu hosts. Ordinary sync preserves foreign links. Brain adoption remains separate.

1. Read the host's actual alias targets and native plugin inventory. Use the approved clean library and exact expected revision/ref. Load the intended installed Skills and Status files; verify enabled native replacements, version/source and all files. A package on disk or planned install is insufficient. Keep dirty checkouts, pins, unrelated skills and existing backups.
2. Write a version 1 manifest with this host's literal `path` and `expectedTarget` pairs. The reviewed tool's allowlist accepts only the historical `.agents/skills` and `.claude/skills` aliases and their original `V:\dev\skills\skills\oneezy\<skill>` or `/mnt/v/dev/skills/skills/oneezy/<skill>` targets. Provide a new durable `--receipt`. Use the canonical script with `migrate-aliases --alias-file <manifest> --receipt <receipt> --repo <library> --expect-revision <full-sha> --remote-ref <exact-ref> --plan --json`. Published deployment requires CLI 0.7.4 or newer; a held reviewed build uses `SKILLS_SYNC_CLI`.
3. Account for every conflict before applying the same command without `--plan`. Each selected host's Skills/Status prerequisites pass together before either alias moves. The tool rechecks the old target and installed replacement immediately before mutation, moves each original link into its harness's `.skills-sync-alias-backups` outside skill discovery, reads it back and records ownership/files in the receipt. It installs no plugins and writes no instruction blocks. An unavailable or changed replacement holds that host; independent verified hosts can continue.
4. Repeat the migration to prove idempotence. Inspect a fresh host's actual default skill inventory: stale unqualified aliases must be absent and current namespaced definitions present. Run an ordinary authorized Skills Sync request, without forcing a selected file, and verify it executes the canonical workflow then invokes installed Status. For Claude, runtime authentication is separate from successful plugin installation. Resolve missing native installation through canonical sync before alias migration; never remove a working alias to hide that failure.
5. Run canonical `status --json`, then invoke `/oneezy-status` Skills Sync mode with command, complete output, exits, readbacks, selection and chaining evidence. Report held hosts and unknowns separately. `rollback-aliases --receipt <receipt> --repo <library>` previews/restores only unchanged backed-up links, retains native plugins and refuses later destination edits. Keep the receipts and backups durable; do not run a broad `unlink` to clear the old aliases.

Claude write flags come from each installed command's help. A failed command includes structured arguments, exit status and stdout/stderr in the sync report. Inspect that evidence and preserve the destination on prerequisite failure; do not blindly repeat registration or patch settings.
