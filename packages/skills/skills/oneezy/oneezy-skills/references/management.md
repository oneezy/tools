# Creator and management actions

1. **Inventory.** Read the packaged capability contract, catalog and host adapter. Identify the exact destination, source owner, saved release, installed version, existing work and current action help/schema. The canonical sync tool generates packages (library commands) and, on a machine, brings each harness to its one form (Claude Code account plugins, Codex and Hermes plugins from GitHub), the one global skills block and the one session-hook entry, removing only its own leftover links. Reuse those workflows. Resolve duplicate/stale standalone skills independently of bundled plugins.
2. **Load.** Skill authoring loads actual skill-creator plus writing-for-agents. Plugin authoring/update loads actual Plugin Creator create-plugin/update-plugin when exposed. ChatGPT discovery/connection loads actual Plugin Management plugin-management. On Claude/Codex load those skills only if present; use the verified local CLI for a local install/update instead of inventing a skill or cloud upload command.
3. **Act.** Follow the host adapter’s ordered native API/CLI route, then another supported route only for absent/technical capability failure. Make the actual structured tool call or shell command. Installing dependencies is limited to this authorized request; a missing connection can be suggested and held while independent destinations proceed. Explicit user-only calls, access denials, acceptance prompts and permission gates stop that destination. No repeated failed attempts or alternate-writer bypass.
4. **Scope.** Authoring changes repository source; packaging runs canonical build --artifacts after checks; sync applies the harness forms, the global block and the hook entry; CLI installation/update targets only the named local host/plugin/scope; eligible account upload uses exact backend ID and expected release. A review/no-publication request performs source/build/test and holds installation/upload. No default blanket installs, permission changes, duplicate deletion, main promotion or cloud updates.
5. **Verify.** Source: tests and canonical check. Package: manifest, dependencies, archive hash and file inventory. Local install/update: CLI result, list/details or loaded inventory, version/cache and fresh session. Account update: returned release and get_plugin_files readback, then fresh chat loading/behavior. A mention or loaded instruction satisfies none of these action checks. Report each destination as executed/verified, held, unsupported or failed, with exact blockers.

For a brief capture dependency, call oneezy-brain and its reusable connector workflow. Do not insert an alternate capture writer in a brief prompt. A standalone cloud Meeting refresh or retirement needs its own exact skill identity and supported delivery action; updating the Oneezy plugin alone leaves it stale.
