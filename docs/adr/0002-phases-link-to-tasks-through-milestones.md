# Phases link to tasks through GitHub Milestones, not sub-issues

A phase is an issue labelled `phase` that the task-manager roadmap command derives from a roadmap markdown file, one per `## Phase <n> — <title>` section, and a task belongs to a phase by carrying the GitHub Milestone of the same title. We chose Milestones over sub-issues because sub-issues are wayfinder's slot: a map's children are its sub-issues, and a phase that also parented them would give every ticket two parents and change how wayfinder claims, links and closes. A Milestone is a built-in field on the issue, set with one `gh issue edit <n> --milestone "<phase title>"`, shows as a marker on the Roadmap view next to the phase's bar, and needs no edge of our own to keep in step. The roadmap file stays the source of truth, so a run rewrites a phase body whose text changed and reports it, while Start and Due stay a human's and are never overwritten; views the spec does not name are deleted on repair for the same reason, so a hand-made board cannot drift back in. Decided on [oneezy/tools#77](https://github.com/oneezy/tools/issues/77) (2026-10-01), replacing the sub-issue wording the glossary carried from [#7](https://github.com/oneezy/tools/issues/7).
