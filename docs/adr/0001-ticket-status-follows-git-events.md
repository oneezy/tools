# Ticket status follows git events, and Done means merged into dev

A ticket's Status on the GitHub project board is never moved by hand; it is derived from repository events. Assignment means Next Up, a branch appearing on GitHub means In Progress, a pull request marked ready means Review, a merge into `dev` means Done, and a promotion of `dev` into `main` means Complete. Done deliberately means merged into `dev`, not shipped: `main` is the default branch and Justin promotes `dev` to `main` by hand, so a Done ticket is finished from the developer's side while Complete answers "is it live". We chose this over a hand-moved board because one person drives many agents in parallel and a board that has to be tended lies within a day; and over GitHub's default closing keywords because those only fire on merges into the default branch, so an Action closes the linked issues on merge into `dev` instead. Blocked is not a column: wayfinder already records it as a native dependency edge, and a second meaning would collide with it. Decided on [oneezy/tools#7](https://github.com/oneezy/tools/issues/7).
